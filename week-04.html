2026-11-01 / 14:00–17:00 KST

Fourth regular meetup: voice tarot flow and character

Venue
Hyundai Motor and Kia headquarters, Yangjae

The team defined the mobile voice tarot journey from social login to the report screen. The target is a launch-ready product for the presentation review at the end of November.

Announcements

  • Teams for the final presentation will be selected after review of the materials submitted at the end of November.
  • Development can continue after submission to improve the project.

User journey

  • Social login screen: Naver, Kakao, and OpenAI.
  • Nickname screen: user input with a random default value.
  • Main screen: reader profile card and a call button that opens the call screen.
  • Call screen: mute and end controls at the bottom, with a real-time activity effect at the top.
  • The user speaks three card numbers from 78 predefined cards. The interface shows a card draw effect.
  • The voice agent explains each selected card, then continues the consultation through voice interaction.
  • The call ends when credits are exhausted or the user selects the end button. The report screen then opens.
  • The report shows the selected cards at the top and the conversation summary below. Show a loading state during summary generation, then return to the main screen.

Character and service concept

  • Start with one confident, direct tarot reader under the Queen mindset concept. Decide later whether to add more readers.

Cost and payment direction

  • Use passes in 10-minute units. A 7-minute consultation uses one pass; a 27-minute consultation uses three passes. Unused time is discarded.
  • Decide later whether to offer a free trial without membership, with API cost as a constraint.

Challenges and adjustments

  • Free trials incur API costs without payment. Conversion to paying membership and the conversion flow are key design questions.
  • Balance membership prompts against user drop-off. Some users may reject the request, while others may be interested.

Next work: November 8

  • Voice implementation: connect the voice API and build an initial prototype that supports real calls.
  • Backend: document the technology stack, data structure, and infrastructure; prepare AWS account setup.
  • Design and planning: make a Figma mood board, collect references, and write sample dialogue and scenarios for the tarot reader.
  • Development workflow: prepare the team Git Flow guide, including AGENTS.md.
